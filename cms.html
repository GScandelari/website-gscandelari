CMS do Blog

Um sistema próprio de gerenciamento de conteúdo, construído do zero para alimentar este blog, pensado desde o início para ser reaproveitado em outros sites.

O que é e por quê

Em vez de depender de um CMS de terceiros para publicar no blog, construí o meu próprio: uma API que guarda os posts no Firestore, e um painel administrativo separado para criar, editar, agendar e gerenciar tudo sem precisar mexer em código ou montar requisições na mão.

O objetivo desde o início não era só resolver esse problema uma vez: era construir algo genuinamente reaproveitável. Toda configuração específica de um site (repositório de destino, bucket de imagens, lista de e-mails autorizados) fica em variáveis de ambiente, não no código. Reaproveitar este CMS para outro site é uma questão de configuração, não de reescrever nada.

Arquitetura

Dois repositórios, cada um com uma responsabilidade clara.

Backend (cms)

API REST em Node.js/Express, publicada como Cloud Function (2ª geração) no Firebase. Guarda os posts no Firestore e as imagens no Firebase Storage.

  • Autenticação dupla: chave de API para scripts, ou token do Firebase Auth com lista de e-mails autorizados
  • Publicação agendada, verificada automaticamente a cada 5 minutos
  • Dispara o rebuild do site (GitHub Actions) sempre que um post é publicado
  • Upload de imagens com validação de tipo e tamanho

Painel (cms-admin)

HTML, CSS e JavaScript puros, sem framework nem build step. Fala diretamente com a API do backend e com o Firebase Authentication.

  • Login com Google, restrito a uma lista de e-mails permitidos
  • Sessão única por dispositivo: logar em um lugar desconecta os outros
  • Sessão encerrada automaticamente após 15 minutos de inatividade
  • Rascunhos de posts salvos automaticamente, recuperáveis em qualquer dispositivo

Principais funcionalidades

Preview em tempo real

Tela dividida: editor de um lado, preview ao vivo do outro, atualizado a cada alteração.

Agendamento de posts

Defina uma data e o post é publicado sozinho, sem precisar estar online na hora.

Biblioteca de imagens

Envie, reaproveite e exclua imagens, com aviso quando uma imagem ainda está em uso em algum post.

Busca e visão geral

Painel com totais por status, e filtros por título, tag, status e data de publicação.

Segurança de sessão

Sessão única por dispositivo e desconexão automática por inatividade.

Recuperação de rascunho

Trabalho em andamento fica salvo automaticamente, mesmo se a sessão for interrompida.

Como reaproveitar em outro site

Nada disso exige mudar código, só configurar.

1

Clone os dois repositórios (cms e cms-admin) e crie um projeto Firebase novo, com Firestore, Storage e Authentication (Google Sign-In) habilitados.

2

Configure os secrets do backend: uma chave de API, a lista de e-mails com permissão de escrita, e (opcionalmente) o repositório do site e o bucket de imagens.

3

Aponte a config do Firebase do painel administrativo pro seu novo projeto, e faça o deploy do backend e do painel.

4

Integre seu site com a API REST do CMS (um simples GET /posts) pra listar e renderizar os posts publicados.
